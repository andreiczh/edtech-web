# P1: согласие, сессии и повторяемость оценивания

Изменения от 02.11.2026 после повторного аудита.

## Согласие на корпус голоса

- В регистрации `corpus_consent` — явный boolean, по умолчанию false. Аккаунт
  и настройка создаются в одной транзакции. Ошибка записи откатывает аккаунт.
- Настройки внешнего вида больше не отправляют согласие. Изменение согласия
  имеет отдельный подтверждаемый запрос; отказ сервера виден пользователю.
- Сервер сливает частичные настройки атомарно. Последняя проверка согласия
  и вставка аудио в корпус выполняются в одной транзакции.
- Версия согласия — 2. Старое true могло быть результатом ошибки регистрации,
  поэтому больше не разрешает сбор. Пользователь может явно включить его
  в кабинете заново. Старые записи этим выпуском не удаляются.

## Сессии

Все защищённые запросы используют `Authorization: Bearer <session_token>`.
Регистрация, вход по паролю и оба входа MAX возвращают прежние id/nickname/exam
плюс session_token и expires_at (Unix seconds). ID аккаунта остаётся неизменным,
по нему сохраняются прогресс, настройки и история. X-Device не даёт доступа.

Срок сессии — 30 дней. В базе хранятся только SHA-256 хеши токенов. Выход через
POST /auth/logout отзывает текущую сессию; сброс пароля увеличивает auth_version
и отзывает все прежние сессии. Проверка не кэшируется. Недоступная база даёт 503,
неизвестная/просроченная сессия — 401. ADMIN_KEY для операционных проверок остаётся.
REQUIRE_ACCOUNT=0 больше не открывает пользовательские данные.

Миграция добавляет auth_sessions и accounts.auth_version, не пересоздаёт таблицы
с аккаунтами или прогрессом. При первом открытии новой версии нужно войти заново.
Сессии не входят в бэкап; восстановление аккаунтов отзывает текущие сессии.

## Оценивание

Чтение проверяется детерминированной сверкой текста, без судьи-LLM. Окончания,
близкие по написанию замены и форматирование чисел не считаются доказанными
ошибками произношения. Они отмечаются как неопределённость. Крупные пропуски,
недочитанный текст и явные лексические подмены продолжают влиять на предварительный
балл. Модель не может добавить отсутствующую в расшифровке ошибку.

Прочие задания сохраняют критерии, персоны и шкалы. Их оценка больше не зависит
от меняющейся истории ученика. Mistral получает фиксированный random_seed;
второй проход монолога использует другой, также фиксированный seed. При отказе
выбранной STT или модели проверки возвращается ошибка, а не оценка от запасной модели.
Откат разговорной модели остаётся. Исправления, совпадающие с исходной фразой,
не показываются и не учитываются как языковые ошибки.

Повторяемость не равна точности относительно эксперта: произношение по тексту
не оценивается. Обновление весов под alias модели также требует повторной
калибровки. Этот выпуск не заявляет улучшенный процент совпадения с ФИПИ.

## Проверки и выпуск

```
npm ci
npm run check
python scripts/test-backend.py
```

P1-регрессии: backend/test_p1.py и scripts/test-p1.mjs. Последний проверяет
настоящий компонент регистрации с разным порядком ввода пароля и согласия.
Проверки запускаются в GitHub Actions на Python 3.11 и Node 22, как в Dockerfile.

После развёртывания: повторный вход, доступ с новой сессией, отказ по прежнему ID,
сохранение/отзыв согласия, logout с повторной проверкой токена, несколько прогонов
одного аудио чтения, остальные три задания и голосовой разговор. Ключи провайдеров
остаются в Render/Windows, в репозиторий и протоколы не попадают.

## Остальные исправления аудита (P2)

- Голосовые запросы аутентифицируются до разбора multipart. Тело ограничено
  26 MiB с учётом служебных полей, включая загрузку по частям без Content-Length;
  предел самого аудиофайла остаётся 25 MiB. Одновременно обрабатываются не более
  четырёх загрузок; на передачу тела отводится 60 секунд. Временные файлы при
  превышении лимита закрываются. Отмена ответа отменяет незавершённый разбор.
- /ping проверяет жизнь процесса, /ready — доступность базы и наличие ключа;
  /health больше не возвращает ok=true при отсутствии базы или ключа.
  Readiness не доказывает доступность LLM: для этого нужен реальный голосовой прогон.
- Разборы с heartbeat считаются по результату как analysis_ok / analysis_failed;
  предварительный HTTP 200 больше не считается успешным разбором. Разговор
  аналогично учитывается как conversation_ok / conversation_failed после потока.
- aiohttp обновлён до 3.14.4; npm lock обновлён совместимыми исправлениями.
- В CI добавлен PostgreSQL 17: проверяются обновление старой схемы с сохранением
  аккаунта, согласие, выдача/отзыв сессий и сброс пароля. Локально этот тест
  пропускается, если отдельная тестовая PostgreSQL не настроена.

## Проверка на Render: фиксированный путь STT

Живой прогон 03.11.2026 обнаружил HTTP 429 у voxtral-small-latest. Прежде
этот отказ скрывался переходом на транскрипционный endpoint. Теперь один путь
выбирается заранее: STT_TASK_MODE=transcription (по умолчанию при Mistral),
модель — STT_REMOTE_MODEL, температура 0.0. Это тот же доступный endpoint,
который проверен голосовым разговором. Случайного переключения между моделями нет.
При локальном STT значение по умолчанию local; chat с STT_TASK_MODEL включается
явно после проверки его квоты. Прежний STT_TASK_MODEL сам по себе больше не
переключает задания на чат-модель. Health показывает выбранный путь и счётчики.

Параметр temperature для транскрипции описан в API Mistral:
https://docs.mistral.ai/api/endpoint/audio/transcriptions

## Два прохода монолога

Два фиксированных прохода запускаются параллельно: второй не зависит от первого.
Это сохраняет консенсус и сокращает ожидание примерно до времени более медленного
прохода. Ошибка одного прохода или неполная структура ответа отменяет оценку;
оставлять только первый проход нельзя — это меняло бы шкалу между повторами.
Сбой необходимой дополнительной проверки спорных пунктов также не выдаёт балл.
