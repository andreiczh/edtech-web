# Деплой на Hugging Face Spaces

Публичная ссылка на Pingo AI. Один контейнер: FastAPI отдаёт и API, и собранный фронт,
поэтому адрес один и никакого CORS.

**Почему именно HF, а не туннель с ноутбука.** 22.07.2026 три попытки поднять `cloudflared`
с машины в РФ упёрлись в обрыв TLS до edge Cloudflare (порт 7844), причём трафик к нему
шёл через VPN-клиент с непрозрачными правилами маршрутизации. Даже если бы туннель встал,
ссылка жила бы только пока ноут включён и не спит, и меняла бы адрес при каждом перезапуске.
HF выбран потому, что он бесплатен, не требует карты и **доступен из РФ** — оттуда уже
качаются веса whisper, то есть доступность проверена практикой, а не статьями.

---

## Что нужно один раз

### 1. Аккаунт и Space

1. Завести аккаунт на <https://huggingface.co> (бесплатно, карта не нужна).
2. **New → Space**. Заполнить:
   - **Owner** — твой ник;
   - **Space name** — `pingo-ai`;
   - **License** — любую;
   - **SDK** — **Docker**, шаблон **Blank**;
   - **Visibility** — Public.

> ⚠️ Public означает, что зайти сможет кто угодно, у кого есть ссылка, и каждый его запрос
> тратит квоту **твоего** ключа Mistral. Пока ссылку никто не знает — риск низкий, но перед
> тем как класть её в чат группы или в соцсети, нужно прикрутить код доступа.
> Private-Space не годится: он открывается только под твоим логином, показать никому нельзя.

### 2. Ключ Mistral — в секреты Space, не в репозиторий

В Space: **Settings → Variables and secrets → New secret**.

- **Name:** `LLM_API_KEY`
- **Value:** ключ Mistral

Больше ничего задавать не нужно: `LLM_BASE_URL`, `LLM_MODEL`, `WHISPER_MODEL` и `TTS_VOICE`
имеют в коде правильные значения по умолчанию (`backend/main.py`, блок «Настройки через .env»).

Файл `backend/.env` в образ не попадает — он отрезан и `.gitignore`, и `.dockerignore`.

### 3. Токен для пуша

<https://huggingface.co/settings/tokens> → **New token** → тип **Write**.

Токен нужен вместо пароля при `git push`. Никому его не пересылай и не вставляй в чат.

### 4. Привязать репозиторий и запушить

```powershell
cd C:\Users\Lenovo\edtech-copilot-web
git remote add hf https://huggingface.co/spaces/ТВОЙ_НИК/pingo-ai
git push hf main --force
```

Git спросит логин и пароль: логин — ник на HF, пароль — **токен** из шага 3.
Windows запомнит его, второй раз спрашивать не будет.

> **Про `--force`.** При создании Space HF кладёт туда свой README, поэтому обычный push
> отклонится. Здесь это безопасно: мы затираем один автосгенерированный файл в **пустом**
> Space. Флаг обязан указывать на `hf`. **`git push origin --force` не делать никогда** —
> это GitHub, там живая история.

## Каждый следующий деплой

```powershell
cd C:\Users\Lenovo\edtech-copilot-web
git push hf main
```

Space сам пересоберётся. Сборка идёт во вкладке **Logs** (пункт «Building»).

---

## Сколько ждать и что должно получиться

- **Первая сборка — 10–20 минут.** Внутри: `npm ci` + сборка фронта, `pip install`
  и скачивание весов whisper (~150 МБ) прямо в образ.
- Веса кладутся на этапе сборки намеренно: иначе каждое пробуждение Space после сна
  означало бы минуты ожидания первого запроса. На этих граблях мы уже стояли локально
  (`DECISIONS.md` §5, п.3).
- Адрес будет вида **`https://ТВОЙ_НИК-pingo-ai.hf.space`**.
- Проверка живости: `https://ТВОЙ_НИК-pingo-ai.hf.space/health` — там должно быть
  `"llm_key": true`. Если `false` — секрет не подхватился, вернись к шагу 2.

## Что честно ожидать от бесплатного тарифа

| | Локально (этот ноут) | HF Spaces (free CPU) |
|---|---|---|
| Процессор | ноутбучный CPU | 2 vCPU, 16 ГБ RAM |
| STT реплики ~10 c | 2.7 c | ожидаемо медленнее, **надо померить** |
| Живёт | пока включён ноут | всегда, но засыпает после ~48 ч простоя |
| Первый запрос после сна | — | долгий: контейнер поднимается заново |

Цифры для HF не измерены — их надо снять после первого деплоя тем же способом, что и
локальные: синтезировать речь через edge-tts и послать в эндпоинт.

**Отдельно проверить после деплоя:** переживает ли прокси HF потоковую отдачу `/talk_stream`.
Локально ровно этот класс бага уже ловили — gzip держал весь поток в буфере до конца ответа
(`DECISIONS.md` §5, п.7). Если HF буферизует так же, стриминг снова перестанет давать выигрыш,
и это будет видно только замером, а не глазами.
