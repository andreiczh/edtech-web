# GoSpeak

Голосовой ИИ-тренажёр устной части ЕГЭ по английскому. Ученик говорит голосом,
система распознаёт речь, разбирает ответ по критериям ФИПИ (задания 39–42) и
отвечает голосом в режиме «Разговор с носителем». Работает как мини-приложение
в мессенджере MAX (бот `@t811_hakaton_max_bot`) и как сайт:
https://pingo-ai-dpd9.onrender.com (телефонная версия с компьютера — `/?mini`).

> Репозиторий называется `edtech-copilot-web` — старое имя того же проекта
> (Pingo AI → GoSpeak). История решений — [`docs/DECISIONS.md`](docs/DECISIONS.md),
> правила для агентов — [`CLAUDE.md`](CLAUDE.md), запуск с нуля для второго
> разработчика — [`docs/ONBOARDING.md`](docs/ONBOARDING.md). API описано
> сервером: `/openapi.json` (OpenAPI 3.1), `/docs`; обязательные проверки —
> [`DATA-API.yaml`](DATA-API.yaml).

## 1. Назначение

Устная часть ЕГЭ — единственная, к которой нельзя подготовиться по учебнику:
нужен собеседник, который слушает, оценивает по официальной шкале и объясняет
ошибки. GoSpeak даёт такого собеседника в телефоне: четыре задания экзамена с
таймингами ФИПИ, разбор по критериям экспертов, свободный разговор с ИИ и
статистика прогресса. Целевая аудитория — 17–25 лет, РФ.

## 2. Основной пользовательский сценарий

1. Открыть бота в MAX → кнопка приложения запускает мини-приложение
   (или открыть сайт в браузере).
2. Вход: внутри MAX — автоматически по подписи запуска (`POST /auth/max`);
   в браузере — регистрация по коду доступа (ник генерируется кнопкой,
   пароль от 8 символов) или вход по нику.
3. Главная → «Начать практику» → выбор задания 1–4 → отсчёт → инструкция →
   подготовка → запись ответа → «Анализ ответа» → разбор: балл по шкале ФИПИ,
   ошибки с поправками, расшифровка, кнопка «не согласен» у каждого спорного места.
4. Вкладка «Разговор»: нажать микрофон, сказать фразу, услышать ответ собеседника;
   с третьей реплики доступен «Разбор беседы».
5. «Статистика»: интенсивность, серия занятий, средние баллы, уровень и XP,
   частые ошибки, календарь.
6. «Настройки»: собеседник (три персоны), субтитры, громкость, избранное, аккаунт.

## 3. Состав и архитектура

Один контейнер = весь продукт: FastAPI отдаёт и API, и собранный React-фронт.

| Часть | Где | Что делает |
|---|---|---|
| Бэкенд | `backend/main.py` | API, отдача `dist/`, вебхук бота MAX, админка `/admin/*` |
| Оценивание | `backend/ege_scoring.py`, `scoring.py`, `ege_prompts.py` | шкалы ФИПИ считает код, модель отвечает на вопросы эксперта |
| Разговор | `backend/dialogue.py`, `talk_review.py`, `personas.py` | лестница глубины, разбор беседы, три собеседника |
| Данные | `backend/storage.py` | SQLite по умолчанию, Postgres по `DATABASE_URL` (прод — Neon) |
| MAX | `backend/max_auth.py`, `max_bot.py`, `max_subscribe.py` | подпись `WebAppData`, бот, подписка на вебхук |
| Фронт | `src/` (React 19 + Vite + TypeScript) | телефонная оболочка `src/mini/*` (MAX, ≤ 820 px), настольная `src/screens/*`, банк заданий и серии `src/ege2/*` |
| Внешнее | Mistral (STT Voxtral, LLM, TTS), платформа MAX, edge-tts (запасная озвучка) | см. раздел 8 |

Поток данных: браузер / WebView MAX → `/task_feedback` или `/talk_stream`
(multipart с записью) → распознавание Mistral → LLM Mistral (+ шкала ФИПИ в коде)
→ озвучка Mistral → JSON / NDJSON обратно. Профиль ошибок, прогресс и настройки —
в базе по заголовку `X-Device` (id аккаунта).

## 4. Запуск одной командой (Docker)

```bash
cp backend/.env.example backend/.env   # вписать LLM_API_KEY (Mistral)
docker compose up --build
```

Открыть http://localhost:8000 (телефонная версия: http://localhost:8000/?mini).
Сборка занимает 3–4 минуты (фронт + pip). Проверка: http://localhost:8000/health →
`"ok": true`, `"llm_key": true`.

Без Docker (так работает разработчик на Windows):

```powershell
cd C:\Users\Lenovo\edtech-copilot-web
npm.cmd ci
npm.cmd run build
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

## 5. Параметры и переменные окружения

Все переменные с дефолтами и пояснениями — [`backend/.env.example`](backend/.env.example).

| Переменная | Зачем |
|---|---|
| `LLM_API_KEY` | **обязательна**: ключ Mistral (распознавание, разбор, озвучка) |
| `MAX_BOT_TOKEN` | сценарий в MAX: вход по подписи и бот; без него сайт работает как раньше |
| `MAX_ID_SALT` | соль id MAX-аккаунтов — задать ДО первых входов, не менять |
| `ADMIN_KEY` | админка `/admin/*` (заголовок `X-Admin-Key`) |
| `INVITE_CODES` | первый код доступа на регистрацию (дальше — в админке) |
| `DATABASE_URL` | Postgres; пусто = SQLite внутри контейнера |
| `PORT` | порт сервера (compose задаёт 8000) |

Фронт: `VITE_BACKEND_URL` (пусто = same-origin, см. `.env.example` в корне).

## 6. Порты

- **8000** — единственный порт: API и фронт; в compose проброшен как `8000:8000`.
  Внутри образа порт берётся из `PORT` (без него — 7860).
- Исходящие соединения: `api.mistral.ai:443`, `platform-api2.max.ru:443`,
  edge-tts (`speech.platform.bing.com:443`, только при `TTS_PROVIDER=edge`),
  Neon Postgres (`5432`, только при `DATABASE_URL`).

## 7. Зависимости

- Python 3.11 — `backend/requirements.txt`, версии закреплены.
- Node 22 — `package.json` + `package-lock.json` (ставить только `npm ci`).
- Базовые образы — `node:22-bookworm-slim`, `python:3.11-slim`.

## 8. Внешние сервисы и интеграции

| Сервис | Зачем | Что нужно |
|---|---|---|
| Mistral API | распознавание (voxtral-mini / voxtral-small для заданий), разбор и разговор (mistral-small, запасная ministral-8b), озвучка (voxtral-mini-tts) | `LLM_API_KEY`; из РФ работает без VPN |
| MAX Bot API | бот, вебхук `/max/webhook`, кнопка мини-приложения, вход по подписи `WebAppData` | `MAX_BOT_TOKEN`; адрес мини-приложения задаётся в платформе MAX для партнёров: Чат-боты → бот → ⋮ → Настройки → URL |
| edge-tts | запасная озвучка без ключа (`TTS_PROVIDER=edge`) | — |
| Neon Postgres | база прода | `DATABASE_URL`; без него — SQLite |
| Render | публичный адрес, деплой по `git push origin main` (`render.yaml`) | — |

Внутри Docker не воспроизводятся Mistral и MAX: для проверки нужны ключ Mistral
и (для сценария в мессенджере) токен бота — оба указаны на первом слайде презентации.

## 9. Работа с данными

- **Аккаунт**: ник (генерируется из английских слов), хэш пароля (PBKDF2-SHA256,
  120 000 итераций), экзамен. MAX-аккаунт — id, выведенный из номера пользователя
  MAX с солью, без пароля.
- **Результаты**: тип задания, вариант, балл / максимум, длительность, дата;
  **ошибки** (цитата → поправка, категория) — для «варианта по ошибкам» и профиля
  ученика в промптах.
- **Жалобы** («не согласен»): причина, комментарий, расшифровка и снимок разбора —
  очередь в админке; вердикт владельца превращает спор в калибровочный случай.
- **Речь не хранится**: запись уходит в распознавание и отбрасывается. Исключение —
  корпус голоса при явном согласии в настройках, с лимитами из `.env.example`.
- **Банк заданий**: встроенные варианты в `src/ege2/tasks.ts` + таблица `tasks`
  (импорт из открытого банка ФИПИ через `/admin/fipi/import`, публикует человек).
- Политика: `/privacy.html`. Бэкап и восстановление: `backend/backup.py`,
  `backend/restore.py` (`/admin/backup`, `/admin/restore`).

## 10. Тестовые данные и учётки

- Код доступа для регистрации: `INVITE_CODES=demo-code` в `backend/.env` или
  создать в админке — `POST /admin/invites` с заголовком `X-Admin-Key`.
  Тестовые логины для жюри — на первом слайде презентации.
- Встроенный банк заданий работает без базы (пять вариантов на номер); полный
  банк (193 задания ФИПИ) — в базе прода, отдаётся `GET /tasks`.
- Экран разбора без микрофона: `/?mini#mini-result` с примером в
  `sessionStorage['gospeak.mini.demo']` (формат — `src/mini/MiniApp.tsx`).
- Речь без микрофона: синтезировать edge-tts и отправить в `/task_feedback` —
  так работает `backend/test_reading_live.py`.
- Приёмочный чек-лист с телефона: `/manual-test.html`.

## 11. Пошаговый сценарий проверки

1. `docker compose up --build`, дождаться `Uvicorn running`, открыть `/health` —
   `ok: true`, `llm_key: true`.
2. Открыть `/?mini` (или сайт с телефона). Зарегистрироваться: ⟳ ник,
   пароль 8+, код доступа. Ожидание: главная с приветствием и ником.
3. «Начать практику» → «Задание 1» → отсчёт 5 с → инструкция → подготовка (SKIP)
   → прочитать текст вслух → «Анализ ответа» → разбор: балл 0–1, слова с ошибками
   подсвечены, карточки «Как это прозвучало» и «Итог».
4. ⚑ «не согласен с баллом» → форма с причинами → «Отправить». Ожидание:
   «Спасибо — разберём»; в админке `/admin` (ключ) жалоба в очереди.
5. Вкладка «Разговор» → микрофон → «Hi! I want to talk about my hobby» → ответ
   голосом (первый звук 2–12 с). Три реплики → «Разбор беседы».
6. «Статистика»: решённое сегодня, серия, средние баллы, уровень и XP.
7. В MAX: открыть бота → кнопка приложения → тот же сценарий, вход без кода.

## 12. Примеры ожидаемого поведения

- Чистое чтение текста задания 1 → `1/1`, ошибок 0 (живой прогон 26.09.2026: 26 с).
- Подмена слова при чтении → слово подсвечено, карточка «вы произнесли / правильно»,
  кнопка озвучки правильного слова.
- Интервью (№41): ответ не по вопросу → «не засчитан» с причиной; по вопросу → зачтён.
- Пустая или короткая запись → «Не расслышал — запись пустая или слишком короткая».
- Сервер спит (Render Free) → «Сервер просыпается… подожди 20–30 секунд».
- Лимит Mistral на основную модель → сервер сам уходит на запасную
  (`/health.llm_fallback`), качество разбора ниже, задержка выше.
- Кириллица или мусор в заголовке ключа → 401, не 500; запись больше 25 МБ → 413.

## 13. Известные ограничения

- Критерий «фонетика» в №39 оценивается по расшифровке, а не по звуку: балл
  ставится за пропуски и искажения слов; замер произношения копится фоном и
  ученику не показывается (`PRON_SHOW=0`).
- Точность монолога №42: 4–6 из 8 работ экспертов в пределах ±1 балла;
  интервью 10/10, чтение 7/7.
- Ключ Mistral бесплатного тарифа: с 22.09.2026 лимит 0 на small/medium —
  работает запасная ministral-8b; в пиках ответ разговора ждёт до минуты.
- Render Free засыпает через 15 минут тишины; первый заход ждёт около 30 с.
- Кнопка бота открывает мини-приложение только после привязки URL в платформе
  MAX для партнёров — это делает владелец бота.
- Картинки заданий 40/42 — заглушки без людей; iOS WebView проверен на запись,
  не на воспроизведение ответа.
- Уведомлений, тёмной темы на телефоне и ОГЭ нет — ряды в настройках выключены честно.

## 14. Остановка и повторный запуск

```bash
docker compose stop        # остановить; данные SQLite остаются в контейнере
docker compose start       # запустить снова
docker compose down        # удалить контейнер (и локальную базу); образ остаётся
docker compose up --build  # пересобрать после правок
```

Прод: `git push origin main` → Render пересобирает образ (3–5 минут), адрес не меняется.
