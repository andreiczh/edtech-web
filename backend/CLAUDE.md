# backend/ — FastAPI, голосовая петля

Весь бэкенд — один файл `main.py` (~435 строк). Дефолты берутся **из кода**
(`main.py:103–109`), а не из `.env.example`.

## Эндпоинты
- `GET /` — раздаёт собранный фронт `../dist`. Если `dist/` нет — отдаёт `test.html`.
- `GET /health` — какой STT/LLM/TTS поднят, есть ли `llm_key` (значение ключа не печатается).
- `GET /test` — старая vanilla-JS страница проверки, показывает задержку по стадиям.
- `POST /talk` — non-streaming: аудио → STT → LLM (80 токенов) → TTS → JSON.
- `POST /talk_stream` — streaming: LLM токенами → режем на предложения → каждое сразу в TTS →
  NDJSON-чанки. Фронт сейчас ходит сюда.
- `POST /monologue` — разбор монолога ЕГЭ, Задание 4: batch STT → один структурный проход
  LLM в JSON-режиме → критерии ФИПИ (4+3+3=10) + ошибки.

## Грабли
- **Запускать без `--reload`** — он роняет запросы в полёте на записи файлов.
- Прогрев STT-модели на `@on_event("startup")`: первый старт долгий (качает ~150 МБ
  без индикатора прогресса) — это нормально, ждать.
- `os.path.isdir(_DIST)` проверяется **один раз при импорте модуля** → после `npm run build`
  бэкенд надо **перезапустить**, иначе он продолжит отдавать `test.html`.
- Все блокирующие вызовы (whisper, LLM) обёрнуты в `asyncio.to_thread` — event loop не
  блокируется. Но модель whisper одна и на CPU: **конкурентные транскрипции сериализуются**.
  Все замеры латентности были однопользовательскими — под пилот это надо перемерить.
- `.env` только локальный, на Windows. В git его нет и не должно быть.

## Оценивание по критериям ФИПИ (29.07.2026)
Три модуля, роли разделены жёстко:
- `ege_prompts.py` — правила проверки из методички ФИПИ 2026 («Говорение»). Модель
  выступает экспертом: отвечает на конкретные вопросы («описано ли второе фото»,
  «принят ли вопрос», «процитируй форму глагола из плана и из ответа»). **Баллов
  модель не ставит вообще** — пока ставила, оценка гуляла между запусками.
- `ege_scoring.py` — официальные шкалы. Максимумы: 1 + 4 + 5 + 10 = 20. Ноль по
  РКЗ обнуляет задание 4 целиком; объём высказывания режет балл (≤7 фраз → 0);
  отсутствие вступления с обращением к другу ИЛИ заключения — потолок 1 по
  организации. Задание 1 сверяется с эталоном по словам через `difflib`.
- `test_ege_scoring.py` (быстрый, без сети) и `test_ege_live.py` (гоняет живую
  модель) — сверка с шестью работами, которые проверили эксперты ФИПИ.

Правишь промпт или шкалу — **прогони оба теста**, иначе оценивание уедет незаметно:
```
.\.venv\Scripts\python.exe test_ege_scoring.py
.\.venv\Scripts\python.exe test_ege_live.py
```

## Две модели распознавания, и это осознанно (29.07.2026)
У режимов противоположные требования, поэтому STT у них разный:
- **разговор** (`/talk_stream`) — `voxtral-mini` через `/audio/transcriptions`,
  ~0.5 с. Здесь видна каждая доля секунды, менять нельзя.
- **оцениваемые задания** (`/task_feedback`, `/monologue`) — `STT_TASK_MODEL`
  (сейчас `voxtral-small-latest`) через `/chat/completions` с требованием
  переписывать дословно. Дороже на 1–3 с, но ученик уже отговорил минуту и ждёт
  разбора, а каждое слово превращается в балл ФИПИ.

**Зачем**: разбор СЧИТАЕТ ошибки ученика, поэтому ошибки распознавания он
записывает ученику в вину. Замер: один и тот же безошибочный монолог с русским
акцентом получал **7/10 на быстрой модели и 10/10 на точной** — три балла из
десяти снимались за шум распознавания. WER на речи с акцентом: 11.8% → 4.0%.

**Грабли, на которые уже наступили:**
- чат-модель принимает **только mp3 и wav**, а браузер шлёт webm → перекодируем
  сами (`_to_wav16k`, PyAV). Без этого точный путь падает на КАЖДОЙ реальной
  записи и молча откатывается на быструю;
- WAV, а не mp3: кодирование mp3 стоит втрое больше процессора, а процессор на
  бесплатном Render — самый дефицитный ресурс;
- откат обязан быть ГРОМКИМ. В `/health.stt_task` видно, сколько запросов ушло
  точным путём, сколько откатилось и какая была последняя ошибка. Счётчик, а не
  только «последняя ошибка»: успешный запрос затирал её, и провал прятался.

**Цена, которую надо помнить:** перекодирование — это процессор. Трое учеников,
сдавших задание одновременно, ждут распознавание ~6 с вместо ~0.5 с (на длинных
монологах — до 20 с). Разговор в это время проседает с 2.0 до 2.2–3.0 с.
Лечится платным тарифом Render, не кодом. Выключается мгновенно:
`STT_TASK_MODEL=""` в `render.yaml`.

## Честное ограничение разбора
Вход разбора — автоматический транскрипт. Произношение и фонетику по нему оценить
нельзя, поэтому промпты прямо запрещают выдумывать фонетические ошибки, а в задании 1
(где официальный критерий — ИСКЛЮЧИТЕЛЬНО фонетика) балл ставится по единственному
видимому признаку: пропущено или переврано ли слово. Ученику это говорится прямым
текстом в разборе. Оценка произношения — отдельная задача с аудио, на потом.

## Картинки заданий: только через свой домен
`GET /img/{photo_id}` тянет картинку с Unsplash и отдаёт со своего адреса. Не
оптимизация: **из РФ без VPN images.unsplash.com не открывается** (TLS-хендшейк
виснет), и задания с фотографиями были без фотографий. Фронт ссылается на `/img/...`,
прямых ссылок на Unsplash в `src/` быть не должно.

## Доступ и память (состояние на 23.07.2026)
- **API закрыт**: тяжёлые эндпоинты (`/talk_stream`, `/task_feedback`, `/monologue`,
  `/talk`) требуют `X-Device` = id существующего аккаунта (проверка кэшируется на
  10 мин; отказ базы = fail-open с логом). `ADMIN_KEY` проходит всегда — для
  смоук-тестов. Выключатель: `REQUIRE_ACCOUNT=0`.
- **Рейт-лимиты** в памяти процесса: голос — 20/мин на аккаунт, 300/день на
  аккаунт, 45/мин глобально; `/auth/*` — 12/мин на IP (адрес берём из
  `X-Forwarded-For` — Render за прокси).
- **Месячный бюджет LLM** (`MONTHLY_LLM_BUDGET`, по умолчанию 30000 запросов,
  0 = выкл): счётчик в памяти + сверка с `usage_daily` на старте и раз в 10 мин.
  При 80%+ И опережении календаря лимиты ужимаются (eco 10/150/30, с 95% —
  low 6/60/15), полный отказ только на 100%. Состояние — `/health.budget_month`.
- **История диалога ЕСТЬ**, но КЛИЕНТСКАЯ: фронт шлёт последние 10 реплик формой
  `history`, сервер их санитизирует (роли, 300 символов) и вставляет между system
  и текущей репликой. На сервере диалог НЕ хранится — намеренно (приватность).
- **Память об ошибках** — `storage.py` (Neon Postgres): профиль ученика и частые
  ошибки типа задания подмешиваются в промпты. Аккаунты и банк заданий там же.
- **Стрик и XP** (24.07.2026): таблица `activity_days` (ученик × московский
  день), XP начисляет сервер — реплика +5 (первые 30/день), вариант 10+балл
  (повтор — половина), серия из 5 — бонус 25 (`session_done=1` с фронта).
  Стрик вычисляется из дней, НЕ хранится; заморозка — один пропуск в ISO-неделю.
  Эндпоинты кабинета: `GET /me/stats`, `GET/POST /me/settings` (белый список:
  theme/volume/show_text), `POST /me/nickname`. Всё за шлюзом аккаунта.

## Чего в бэкенде НЕТ (частый ложный вывод)
- Нет разбора в конце сессии для разговорного режима.
- Нет хранения транскриптов речи — только ошибки и баллы (решение владельца).
