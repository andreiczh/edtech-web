# src/ — фронтенд

React 19 + Vite 6 + TypeScript, **обычный CSS**. Tailwind осознанно не берём.
Две оболочки: **настольная** (`src/screens/*`, рейл навигации, стили
`design/*.css`) и **телефонная** (`src/mini/*`, стили `mini/mini.css`) — вторую
выбирает `useMobileShell` (MAX или окно ≤ 820 px). Общее для обеих: вход
(`auth/*`, `screens/AuthScreens.tsx`), аккаунт и настройки (`account/me.ts`),
банк заданий, серии, разбор и споры (`ege2/*`), разговор (`useConversation.ts`,
`talk/*`), MAX (`max/bridge.ts`), форма «не согласен» (`components/Disagree.tsx`).
Модалки рендерятся порталом в `document.body` — иначе `backdrop-filter`
родителя делает их контейнером для `position: fixed`.

## Обращение к бэкенду
Только **относительные** пути: `/talk_stream`, `/task_feedback`, `/me/stats`…
Дефолт `BACKEND` — пустая строка (same-origin), потому что бэкенд сам раздаёт
собранный фронт. В dev (`npm run dev`, :5173) маршруты проксируются на :8000
через `vite.config.ts` — новый маршрут бэкенда добавляй и туда. Override —
`VITE_BACKEND_URL`. Аккаунт узнаётся по заголовку `X-Device` (`identityId()`);
ответ 401 от `/me/*` означает «аккаунта нет» — `App` по `onUnauthorized`
выходит и показывает вход (§6.47).

## Ошибки — человеку, а не коду
`backendError.ts`: 502/503/504 без тела — «сервер просыпается» (Render Free
спит после 15 минут), обрыв сети — «нет связи». Наш бэкенд на своих ошибках
всегда шлёт `detail` (иногда в теле 200 — heartbeat), его и показываем.

## Разговор и разбор (04.08.2026)
- **Темы на экране НЕТ и не должно быть.** Полоса с названием темы прожила
  один день и убрана: человек говорит о чём хочет, подстраивается система.
  Глубину разговора держит сервер (`backend/dialogue.py`), экрану об этом знать
  не нужно — он показывает только круги, микрофон и ответ.
- `talk/review.ts` + `talk/ReviewCard.tsx` — разбор в конце беседы. Кнопка
  «Разбор» появляется только с третьей реплики: разбор стоит вызова LLM, и
  жечь его на «привет-привет» незачем.
- `useConversation` держит ВСЮ сессию (48 реплик), а в промпт шлёт хвост из 16:
  разбору нужен весь разговор, модели — только недавнее. Контекст звука
  создаётся по тапу на микрофон (iOS/WebView иначе молчат), запрос под
  сторожем 75 с, ответ без звука (`silentReply`) показывается текстом даже
  при выключенных субтитрах (§6.47).

## MAX и запись с микрофона (15.09.2026)
- `max/bridge.ts` — признак запуска из MAX (фрагмент `#WebAppData=` → флаг
  в sessionStorage) и ленивая загрузка MAX Bridge. `bootMax()` в `main.tsx`
  ждёт библиотеку ДО первой отрисовки, если мы во фрейме или пришли с
  max.ru (веб-версия MAX данных в адрес не кладёт, §6.45). В обычном
  браузере библиотека MAX не грузится вовсе.
- Личная ссылка от бота (`#mlogin=`, §6.50): `captureLinkLogin()` в `main.tsx`
  забирает токен до первого экрана и стирает его из адреса; `maxlogin`
  входит по нему (`loginMaxLink`) раньше, чем по данным запуска MAX.
- Маршрут `maxlogin` (`MaxLoginScreen` в `AuthScreens.tsx`): вход сам, при
  ошибке — повтор и запасной вход по нику. Новому MAX-аккаунту согласие на
  корпус выставляется в «нет»: экрана согласия в MAX нет.
- Запись: MediaRecorder создаётся ТОЛЬКО через `ege2/audioMime.ts`
  (`makeRecorder`), blob подписывается `recordedType`, имя файла —
  `audioFileName`. iPhone пишет mp4, а не webm; новые места записи — только
  через эти три функции. Подробности — `docs/DECISIONS.md` §6.37.

## Мини-приложение — телефон и MAX (22.09.2026)
`src/mini/*`, стили `mini/mini.css`. Включается `useMobileShell` (MAX или
окно ≤ 820 px) — `App.tsx` тогда рисует `MiniApp` вместо каркаса с рейлом.
Все размеры — пункты макета × `--u`; ничего «на глаз» не двигать: макет —
источник правды, расхождение мерится сверкой по пикселям (§6.39). Иконки —
`mini/icons.ts` (генерируется, руками не править). Поток задания —
`Practice.tsx` (сейчас только №39), разбор — `ResultScreen.tsx`. Прежние
настольные экраны в `.mini-legacy` остались только у запасной ветки
задания (`legacy`); все разделы телефона — свои (§6.43, §6.46). Просмотр разбора без микрофона: `/#mini-result` + пример в
`sessionStorage['gospeak.mini.demo']` (`taskId` выбирает экран); поток только
с нужными номерами — `/#mini-practice=40`; телефонная версия с компьютера —
`/?mini`. Тренажёр: `TaskPicker.tsx` (выбор 1–4, макета нет — собран из
элементов соседних) → серия из пяти вариантов; DEMO — тот же `Practice` по
одному варианту каждого номера. Все четыре номера — свои экраны в
`Practice.tsx` (`ReadingTask`, `DialogueTask`, `InterviewTask`,
`MonologueTask`); разборы — `ResultScreen.tsx` (№39), `ResultScreen40.tsx`
(№40 и №41), `ResultScreen42.tsx` (№42). Ветка `legacy` (прежний
`TaskScreen`) — запас на номер без макетов (§6.44).
Масштаб `--u` считается и по высоте окна (`svh`): кадр без скролла, на
коротком окне всё мельче — так и задумано (§6.42). Префиксы «№39:» /
«Task 1.» на экране срезает `cleanBrief`. Проверка потока без ожидания: в
консоли подменить `Date.now`
(сдвиг вперёд заканчивает таймер) и `getUserMedia` (осциллятор в
MediaStreamDestination) — §6.41. №40: `DialogueTask` + `ResultScreen40.tsx`;
общие звёздочка, нижняя панель разбора и «Назад» (`BackButton`, `useMaxBack`)
— `ResultBits.tsx`; «Назад» ведёт на экран, с которого пришли (§6.45).

Основные экраны (24.09.2026, §6.43): `MiniHome.tsx` (макет 69),

Сращивание с бэкендом (25.09.2026, §6.46): блоки, которых нет в макетах,
